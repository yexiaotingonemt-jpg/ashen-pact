# 我方随从能力来源反馈 · 2.3

日期：2026-10-24。

之前治疗、抽牌、护甲等数字会直接改变，随从发动能力的来源不明显。本版在触发时标出来源单位、能力名称与实际效果，并将表现指向英雄、随从或实际新抽到的牌。

| 能力 | 可见反馈 |
| --- | --- |
| 书契 | 因果织者亮起，说明抽牌结果，新牌高亮；手机将新牌移入可见区域 |
| 见证 | 违约见证者亮起并指向英雄，说明该来源提供的护甲 |
| 复苏 | 薪火祭司亮起并指向英雄，显示实际恢复生命；满血明确显示 0 |
| 共鸣 | 灼刃骑士亮起，说明施放法术后攻击 +1 |
| 启示 | 烛光先知入场后说明实际抽牌结果 |
| 汲取 | 不灭火凰或暮色收割者攻击后标明实际恢复生命 |
| 守卫、圣盾 | 与敌方命中同时显示拦截目标、圣盾实际抵消的伤害 |
| 突袭 | 入场后明确提示即可攻击 |

我方攻击约 380 毫秒，召唤约 420 毫秒；普通来源触发各展示约 380 毫秒。多来源依次说明，防御触发合并在当前命中中，保留攻击者到目标的箭头。能力说明置于箭头之上，单位上的能力名避开箭头终点。

## 实现边界

`actionFeedback` 返回最终合法状态与独立触发元数据；`enemyTurnPlayback` 的既有帧附加该步骤的触发，并单独返回回合开始的尾部触发。元数据不写入存档，不增加规则日志、FX ID 或随机调用，也不改变战斗数值。实际进入手牌的 UID 用于高亮新牌；溢出、疲劳、满血按实际结果说明，不伪报成功抽牌或治疗。

界面沿用最终状态与显示快照分离的方式，播放期间锁定战斗输入；重开取消旧播放。终局弹窗在表现结束后出现，中间帧不保存，刷新不重新执行触发。敌方命中后的普通数字特效先退去，再显示后续来源说明，避免遮挡。

## 验证

- 新增 16 项因果测试，全套 102 项通过，覆盖九类能力、抽牌实际 UID、手满、疲劳、满血、死亡来源、多个来源、敌方帧与尾部触发分配。
- 与改动前引擎独立对照 24 局、4,562 次操作、716 次结束回合。最终状态所有字段完全一致；既有帧去除新增 `triggers` 后也完全一致，包含随机种子、ID、日志、特效和原有快照。1,254 次来源触发没有重复归类。
- 正常浏览器对局验证我方召唤与突袭、攻击、织者首次操纵后抽牌和新牌高亮、祭司治疗、见证者加甲、守卫拦截。桌面与 390×844 手机均核对实际画面。
- 手机正常对局中，新抽到的牌自动进入可见范围；治疗提示播放中刷新，第 8 回合的 31 生命、6/8 能量及 8 张手牌保持一致，输入正常解锁。
- 另用仓库外固定局面副本验证稀有能力：圣盾抵消 2 伤害、先知启示、骑士共鸣、火凰汲取使英雄 25→27 生命，以及两个织者逐个触发后第一张成功进入手牌、第二张溢出到弃牌堆。固定入口和场景数据未加入生产构建；这些专项复验不冒充自然通关。
- 手机较长防御与溢出说明能完整换行，没有覆盖手牌；测试页未记录前端错误。
